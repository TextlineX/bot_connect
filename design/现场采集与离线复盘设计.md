# 现场采集与离线复盘设计

目标：在机器人现场把**运动 + 多路视频 + WS 事件**一次性采集完整，离开机器人后只用 `runs/<run_id>/` 目录即可复盘/对齐/分析。

## 设计原则

1) 现场操作要“少步骤、可重复、可中断”。  
2) 采集结果要“可带走、可复现”，不依赖现场网络/设备。  
3) 采集链路优先稳定：尽量复用 `ffmpeg`、JSONL 等通用工具。  
4) 运动链路必须可判定“真动/假动”：避免 ROS 不可用时返回“看似成功”。

## 采集包目录结构（规范）

建议所有采集都落到 `runs/<run_id>/`，其中 `<run_id>` 使用时间戳或任务号，例如 `20260424_1500`。

```
runs/<run_id>/
  ws.jsonl
  summary.json
  summary.md
  video/
    manifest.json
    <label>_YYYYmmdd_HHMMSS.mp4
    <label>_ffmpeg.log
```

- `ws.jsonl`：WebSocket 消息录制（逐行 JSON）。  
- `video/`：按路数并行录制，按时间戳分段 mp4。  
- `summary.*`：离线分析生成的摘要，快速判断“运动是否真实、流是否录到”。  

## 现场采集流程（推荐“一键”）

在 PC 上使用：`scripts/capture_run.ps1`。

### 1) 启动后端

先在 PC 启动后端（HTTP+WS 同端口），用于：
- WS 中转与日志汇聚
- `/proxy/robot/*` 代理（让 PC 侧同源拉机器人热点 MJPEG）

示例：
```
powershell -ExecutionPolicy Bypass -File scripts\start_backend.ps1 -Port 8765 -AsrMode master
```

### 2) 机器人上启动从机（负责运动与推流）

机器人侧：
- `WS_URL=ws://<PC_IP>:8765`
- `STREAM_MODE=http_mjpeg`
- `STREAM_PUBLIC_HOST=192.168.88.88`（或机器人热点 IP）
- `STREAM_HTTP_BASE=8000`（多路 MJPEG 从 8000 起）

然后执行：
```
bash scripts/start_slave.sh
```

### 3) PC 上开始采集（WS + 视频）

示例（rear/left/right 三路）：
```
powershell -ExecutionPolicy Bypass -File scripts\capture_run.ps1 ^
  -WsUrl ws://127.0.0.1:8765 ^
  -DurationSec 1800 ^
  -RunId 20260424_1500 ^
  -Types "status,result,vision" ^
  -Streams @(
    "rear=http://127.0.0.1:8765/proxy/robot/mjpg?port=8000&path=/stream.mjpg",
    "left=http://127.0.0.1:8765/proxy/robot/mjpg?port=8001&path=/stream.mjpg",
    "right=http://127.0.0.1:8765/proxy/robot/mjpg?port=8002&path=/stream.mjpg"
  )
```

完成后会自动运行离线摘要生成（`scripts/analyze_run.py`）。

## 运动真实性判定（防止“假成功”）

### 问题背景

运动输出在 `common/motion_controller.py` 中统一封装。若机器人侧 ROS/AimDK 依赖不可用，控制器会退回 `sim_mode`，此时：
- WS 层仍然能返回 `ok: true`
- 但机器人底盘不会收到真实速度输出

### 解决策略

在 status 中显式暴露：
- `motion.controller.sim_mode`
- `motion.controller.ros.ready`
- `motion.controller.transport`

离线复盘时看 `runs/<run_id>/summary.md` 即可快速判断。

## 视频采集可靠性（避免静默失败）

### 问题背景

从机在 `STREAM_MODE=http_mjpeg` 时会拉起多个 `scripts/mjpeg_http_server.py` 子进程。若 stdout/stderr 全丢弃，常见错误（订阅失败/端口冲突/ROS 不可用）会“无声失败”。

### 解决策略

从机侧把 MJPEG 子进程 stdout/stderr 落盘到：
```
runs/stream_logs/mjpeg_<port>_<topic>.log
```

现场出现“前端打不开/录不到视频”时，第一时间看该日志即可定位。

## 离线复盘（离开机器人后）

你只需要带走 `runs/<run_id>/`。

建议复盘顺序：
1) 打开 `runs/<run_id>/summary.md`：快速看运动是否真实（`sim_mode/ros.ready`）、视频是否有 mp4。  
2) 若无视频：查看 `runs/<run_id>/video/*_ffmpeg.log` 是否 timeout/404。  
3) 若运动无效：查看 `ws.jsonl` 中 slave 的 `status.motion.controller` 字段。  
4) 需要更深分析：按时间戳对齐 `ws.jsonl` 与 `video/*.mp4`（视频分片文件名自带时间戳）。

## 脚本清单

- `scripts/capture_run.ps1`：PC 一键采集（WS + 多路 MJPEG）。  
- `scripts/record_ws.py`：WS 录制为 JSONL。  
- `scripts/record_mjpeg.py`：多路 MJPEG -> mp4 分段录制。  
- `scripts/analyze_run.py`：离线汇总生成 `summary.json/summary.md`。
